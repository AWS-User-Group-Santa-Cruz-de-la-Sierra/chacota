# Rifa solidaria, sorteo con duendes al agua: plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Una tercera actividad, Rifa solidaria. El admin arma la bolsa escribiendo nombres o con el QR, y cada ronda manda X personas "al agua" con escenas de duendes antes de mostrar al ganador. Incluye un cambio de plataforma: sesiones sin celulares y pantalla final propia de la actividad.

**Architecture:**
- La rifa es una actividad con sesión en el servidor en los dos modos. El modo lista es una sesión "sin celulares": arranca sin lobby, nadie se une y su registro vence a las 48 h.
- El sorteo vive en `advance` (botón principal, clicker y teclado). Sortea con `crypto.randomInt`, guarda con `live.transition` y publica un solo evento `rifa.round` con la secuencia completa y `startsAt`.
- La pantalla grande y los celulares reproducen la ronda desde ese evento, sincronizados con el reloj del servidor.
- La lógica de la bolsa es pura (`bag.ts`, `timeline.ts`) y se testea sin DynamoDB.

**Tech Stack:** pnpm monorepo, TypeScript, Hono, DynamoDB (lib-dynamodb), AppSync Events, Next.js 16 + next-intl 4, React 19, SVG con animaciones CSS, Vitest con DynamoDB Local, playwright-core.

**Spec:** `docs/superpowers/specs/2026-11-24-rifa-design.md`. Los bocetos están en `.superpowers/brainstorm/27589-1795497188/content/` (fuera de git):
- `pantalla-admin.html`: opción B.
- `escenas-al-agua-v2.html`: las cuatro escenas, el ganador, los dos celulares y el SVG del duende (`d-body`, `d-hat`).

Son la referencia visual. Sus animaciones están en bucle, y en el producto se reproducen una sola vez.

## Global Constraints

- Imports entre paquetes del workspace **sin** `.js`.
- `packages/core`, `packages/db` y `packages/live` no mencionan "rifa", "tiluchi" ni "embolsau". La rifa no importa nada de otra actividad.
- Sin infraestructura nueva: ni tablas, ni GSIs, ni Lambdas, ni variables de entorno. El estado va en `session.state`, y si hace falta algo aparte, va bajo `sessionKeys.module(sessionId, 'rifa', ...)` con `ttl: live.ttl()`.
- El reloj es siempre `live.now()` y el azar, `crypto.randomInt`, inyectable en los tests. Ni el navegador ni el celular deciden nada.
- **Id** `rifa`. Manifest con `status: 'experimental'`, `usesPhones: true` y `color: '#C2185B'` (rosado de carnaval; blanco encima da ≥ 4.5:1).
- **Al agua por ronda (X):** de 0 a 5, por defecto 2. Con `n` en la bolsa salen `k = min(X, n − 1)` al agua y 1 ganador. Bolsa vacía: no se sortea.
- **Nombres (modo lista):** uno por línea, recortados, sin líneas vacías; de 1 a 40 caracteres cada uno, de 2 a 500 nombres. Los repetidos cuentan como boletos separados. **Título:** hasta 80 caracteres, por defecto "Rifa solidaria". **Modo QR:** sin `maxPlayers`.
- **Escenas:** `retrete` (7 000 ms), `globazo` (7 000 ms), `lagarto` (7 500 ms) y `micro72` (9 000 ms). Ganador: 6 000 ms. Arranque: `startsAt = now + 1 500 ms`.
- Mientras se reproduce una ronda (`now < round.endsAt`) no se sortea ni se reinicia. Descartar y devolver sí se puede.
- Textos en español con voseo y en inglés: `modules/rifa/messages/{es,en}.json`. Lo de plataforma, en `apps/web/messages/{es,en}.json`.
- Commits: uno por tarea, en la rama `feat/rifa`. Nunca `.claude/`, `.env*`, `.superpowers/` ni `.impeccable/`. Cada mensaje termina con `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Recargar o reconectarse a mitad de una ronda.** La pantalla grande o el celular retoman la escena en el punto exacto, no desde el principio. Si la ronda ya terminó, muestran el resultado, y nunca se sortea de nuevo. → Task 3, `stepAt jumps into the running step`, y Task 4, `snapshot resumes mid-round`.
2. **El evento llega tarde** (red lenta, después de `startsAt` o de `endsAt`). La pantalla entra en el paso que corresponde según el reloj del servidor o muestra el final, sin reproducir de más. → Task 3, `stepAt before startsAt waits and after endsAt is done`.
3. **Dos pestañas del admin.** Un sorteo desde una pestaña lo reproducen las dos. La otra pestaña tiene la versión vieja: su próximo botón se rechaza una vez y el siguiente funciona. Nunca salen dos rondas. → Task 4, `concurrent advances draw once`.
4. **Nombres largos o raros** ("María de los Ángeles Gutiérrez", emojis, nombres repetidos). Entran en el cartel achicando la letra, y los cartelitos de la bolsa no rompen la grilla. → Task 6, `fitTagFont shrinks long names`, y Task 3, `parseNames keeps duplicates and drops blank lines`.
5. **Descartar a todos.** Con la bolsa vacía, el botón se apaga y `advance` no hace nada. Al devolver a uno, se vuelve a poder sortear, y ese uno gana directo. → Task 4, `empty bag does nothing until someone is restored`.

- Produces (`bag.ts`):
  ```ts
  export type RandomInt = (max: number) => number; // entero en [0, max)
  export function bagEntries(entries: Entry[], state: Pick<RifaState, 'discarded' | 'won'>): BagEntry[]
  export function drawRound(pool: Entry[], state: RifaState, now: number, randomInt: RandomInt): Round | null
  export function applyRound(state: RifaState, round: Round): RifaState
  export function setStatus(state: RifaState, entryId: string, to: 'bag' | 'out'): RifaState // un ganador no cambia
  export function resetBag(state: RifaState): RifaState // discarded = [], won = [], winners + { kind: 'reset' }; no agrega dos marcas seguidas ni una marca sin ganadores antes
  export function isPlaying(state: RifaState, now: number): boolean // round !== null && now < round.endsAt
  ```
  - `drawRound` devuelve `null` si `pool` está vacío. Si no, elige `k + 1` entradas distintas con un Fisher–Yates parcial sobre `randomInt`: las primeras `k` van al agua y la última gana. Cada al agua lleva `SCENES[randomInt(4)]`.
  - Tiempos: el primer paso arranca en `now + LEAD_MS` y cada paso siguiente cuando termina el anterior (`SCENE_MS[scene]`). El ganador arranca después del último al agua y `endsAt = winner.startsAt + WINNER_MS`.
  - `n = state.rounds + 1` y `onOverboard = state.onOverboard`.
  - `applyRound`:
    - `won += winner`;
    - `discarded += out`, solo si `round.onOverboard === 'discard'`;
    - agrega `{ kind: 'win' }` a `winners`;
    - actualiza `rounds` y `round`.
- Produces (`timeline.ts`):
  ```ts
  export type Step = { kind: 'waiting'; inMs: number } | { kind: 'out'; index: number; elapsed: number } | { kind: 'winner'; elapsed: number } | { kind: 'done' };
  export function stepAt(round: Round, now: number): Step
  ```

**Files:**

**Interfaces:**
- Consumes: Task 1 (`phones`, `finalSnapshot`) y Task 3 (todo `bag.ts`, `timeline.ts` y `parseConfig`).
- Produces:
  ```ts
  export function createRifaActivity(opts?: { randomInt?: RandomInt }): ActivityServer<RifaConfig, RifaState> // por defecto crypto.randomInt
  export const rifaActivity = createRifaActivity();
  ```
- `prepare(content)`:
  - Lee `parseConfig` y usa como título `title.trim()` o `DEFAULT_TITLE`.
  - Estado inicial `{ onOverboard: 'return', discarded: [], won: [], winners: [], rounds: 0, round: null }`.
  - Modo lista: `entries` con ids `L0…`, `opened: true` y `phones: false`.
  - Modo QR: `opened: false`.
- `advance(live, s)`:
  - Si `!opened`, hace `transition` con `opened: true` y no sortea.
  - Si `isPlaying` o la bolsa está vacía, devuelve `s` sin cambios. No lanza error, porque el marco solo atrapa `invalid_transition`.
  - Si no:
    1. `drawRound` con `randomInt`.
    2. `transition(applyRound(...))`.
    3. Publica `{ type: 'rifa.round', round }` en `channels.public`.
    4. En el modo QR, `live.addScore(sessionId, winner.entryId, 1)`.
  - La bolsa es `entries` en el modo lista, o `listPlayers` → `{ id, name: nickname }` en el modo QR, pasada por `bagEntries` y filtrada a `status === 'bag'`.
- `hostActions` (cada una lee la sesión fresca, transiciona con versión y devuelve `{ version, ... }`):
  - `setOnOverboard({ value: OnOverboard })` → `{ version, onOverboard }`.
  - `discard({ entryId })` y `restore({ entryId })` → `setStatus`, publican `rifa.bag { changes: { [entryId]: 'out' | 'bag' } }` y devuelven `{ version }`. Si el id no existe o es un ganador, no cambian nada.
  - `reset()`: si `isPlaying`, no hace nada. Si no, `resetBag`, publica `rifa.bag { reset: true }` y devuelve `{ version }`.
  - `bag()` → `{ version, entries: BagEntry[] }`.
- `snapshot`:
  - Presentador → `HostSnapshot`.
  - Jugador → `PlayerSnapshot`, con `wins` = rondas de `winners` donde `entryId === playerId`.
- `finalSnapshot`:
  - Presentador → `{ winners }`.
  - Jugador → `{ winners, wins }`.
- `results`:
  - Columna `{ key: 'won', label: { es: 'Ganó en', en: 'Won in' }, format: 'text' }`, con el valor "1, 4" (números de ronda) o `null`.
  - `details: { winners }`.
